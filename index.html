1. Describe reasons why so many companies are using cloud based email and calendar services.

Cloud-based email is an internet-based service, which is hosted and accessed online. Service providers monitor and back up the email network, so there is no need for physical server hardware and ongoing server maintenance like in on-premises services. Key benefits of using cloud-based services include cost savings, increased uptime, scalability, remote access, and improved security.

Paying a monthly subscription fee to a provider (Gmail, Outlook, ProtonMail) will likely be cheaper than maintain your own hardware. Unlike on-premises setups where a local server crash takes down email, cloud services keep communication online during local outages. Scaling is also easier without a need to invest in any expensive infrastructure. Tailored storage capacity and user count are easy to set up for your needs. Also, for small businesses security is typically better in cloud, since large corporations can use more resources toward securing your data than you can alone. Remote access is also much simpler.

4. Compare few cloud data storage provider features and pricing (either for home users or for enterprises)

For comparison, Google Drive, Dropbox, and OneDrive have been selected.

Google Drive offers the most free storage with 15 GB per user. Starting prices for 100GB begin only from 1,99$ per month. Capacity can be extended up to 30 TB, and the number of connected devices is unlimited. Multiple people can edit the same document simultaneously in real time. The interface has quite a lot of features, which can be overwhelming at first. For privacy-oriented users, Google holds the encryption keys, so technically they can access your files if required by law.

Dropbox offers 2 GB for free users and can be extended to 3 TB for 16,58$ a month. It stands out primarily for its file-sharing and sync capabilities. Block-level sync means the service only uploads the changed portions of a file, not the entire file. This can be useful for video editors or anyone working with large assets. The interface is said to be one of the cleanest in industry, avoiding unnecessary toolsets.

For free users, OneDrive offers 5 GB of free storage and can be increased up to 1 TB for one user for 9,99$ a month. The service integrates well into Windows 11, syncing many folders automatically without manual configuration. Protecting certain folders with additional identity verification, such as SMS or authenticator app, is possible, which locks the folder after 20 minutes of inactivity.

3. Select and describe 2-3 well-known Amazon S3 data leak incidents. What went wrong? List some automated S3 bucket search engines and attack tools.

In the capital one hack, former Amazon employee stole over 100 million consumer applications for credit from Capital One. The reason was misconfigured open-source Web Application Firewall (WAF). Attacker exploited a Server-Side Request Forgery (SSRF) vulnerability, in which a server can be tricked into running commands that it should not be permitted to run. Misconfiguration allowed intruder to trick the firewall into relaying requests to a key back-end resource (metadata) on the AWS platform. WAF was assigned too many permissions, allowing to list all of the files in any buckets of data, and to read the contents of each of those files. The intruder used those credentials to exfiltrate massive amounts of customer data [1].

In 2017, a cyber risk team discovered that four Amazon Web Services S3 storage buckets belonging to Accenture were left unsecured and publicly downloadable to anyone who entered the buckets web addresses into their internet browser. Buckets contained cloud platform credentials and configurations, such as internal API configurations, production VPN keys, decryption keys and private SSL signing certificates. Also about 40 000 passwords plaintext passwords were available. To secure the buckets, a simple password requirement for each bucket would have worked[2].

Amazon S3 bucket scanners are typically used for asset discovery, penetration testing and security assessment by security professionals. Popular bucket scanners include AWSBucketDump, BuQuikker, Bucket Finder and S3Scanner [3]. Many different tools for attacking exist. Attackers can overwrite stored assets, enabling them to deface websites or distribute malicious payloads to end users. These exploitation scripts can inject malicious JavaScript directly into site code to steal sensitive information or hijack visitors’ machines for in-browser crypto mining. Attackers can also encrypt bucket files for extortion [4].

4. What would a mid-size company store to the Amazon Glacier? What not? Why? What other large cloud backup or mass storage providers are there?

When companies grow, the amount of data tends to increase rapidly. Organizations often need to retain backups for business or disaster recovery and also for different kinds of records. As the volume of data grows, optimization of costs should be done.

Amazon S3 offers four storage classes designed to lower cost for archiving data, and selecting the right one requires some key considerations. Based on the data access patterns, the time to access files can take from milliseconds up to 48 hours. This depends if the data is rarely accessed, but still needs immediate access, or you need to retain the data for decades, but access is allowed to take several hours. Unlike storage where files are accessed synchronously, certain Glacier tiers require an asynchronous RestoreObject request before the data can be downloaded. Workflows have to be designed to accommodate retrieval wait times ranging from minutes up to 48 hours. Objective count and file sizes also affect costs, since small files have high transition fees and a mandatory 40KB metadata storage overhead per object, which is a small fraction for larger objects. Small files should be aggregated into larger archives, such as TAR bundles, before moving to Glacier, cutting efficiently transition costs and eliminating per-object metadata overhead. Also, large restores should be requested in chronological order based on the object creation times to avoid severe daily throughput limits placed on random requests [1].

For a small and medium-sized balancing between the correct option is vital for the budget. Amazon S3 Glacier is a viable option since it is designed for long-term data retention at a low cost. It is intended for data that is not accessed often, but must be stored securely, such as record, backup files and different documents. In other words, it trades off speed for savings. Compared to other Amazon S3 storage classes, it pills significantly less per stored GB. Companies that use Glacier can be healthcare related, storing medical imaging files, audit logs and compliance archives. Generally other files can be, monthly backups, quarterly backups, financial records, historical trial data and many more possibilities [2].

Although storing data is cheap in Glacier, for day-to-day storage it is not. Glacier is “cold storage” solution, meaning storing data for long periods of time, often years. There is a minimum time period of 90 to 180 days for cold data storage. If that is not reached or data is changed before that date, Amazon charges for an early deletion fee, which could be over half for what you paid for the storage itself. Also retrieving the data immediately is costly, so if you need that data instantly other solutions might be better [2].

Alternatives as a major mass storage for Glacier include Microsoft Azure Blob Storage, Google Cloud Storage and Backblaze B2. Google and Microsoft offer similar classes with retrieval delays and data retention as Glacier. Backblaze is designed as a single-tier solution, no matter how often you need to access it [3].
